## Meeting Notes

### This Week in HLSL

There were 39 PRs merged in HLSL-related areas this week.

* The HLSL frontend added a few semantics and matrix support for `step`.
* The DirectX backend was largely unchanged, only seeing miscellaneous cleanup.
* The SPIR-V backend saw various bug fixes and efforts to re-enable spirv-val,
  as well as some new lowerings.
* The offload test suite received several tests for derivatives and removed
  stale XFAILs.
* New pass manager work continued for both DirectX and SPIR-V, including
  ports of several DirectX passes and SPIR-V pipeline improvements.

30 new PRs were opened, and there are 75 ongoing PRs.

For a full list of merged PRs, see the appendix.

### SPIR-V Datalayout and `p:32:32`

@dnovillo discussed solving llvm/llvm-project#238995 by setting 32-bit pointers
in the DataLayout for logical SPIR-V. It was concluded that this seems sound
enough but we may need to be careful about future compatibility.

### Defaulting to DXC extensions

@dnovillo asked about enabling `-fspv-extension=DXC` for `clang-dxc` by
default, as suggested in llvm/llvm-project#237364. Nobody could remember if
there was a specific reason we didn't do this when introducing the DXC
extension set, but assuming there wasn't there are no objections.

### SV_InstanceID and SV_VertexID

@jzakharovnv talked about the ["What should `SV_InstanceID`/`SV_VertexID`
default to?" RFC][RFC-92447]. There was some agreement that DXC compatibility
is valuable, but that we don't necessarily need to add every single `dxc` flag
to `clang-dxc` without evidence of its use.

### Legalizing Resource Handles in the SPIR-V Backend

@dnovillo filed llvm/llvm-project#234940 a while back and asked for feedback on
the proposed approach. @bogner and/or @hekota are to follow up on the issue.

### `[[vk::push_constant]] ConstantBuffer<T>`

@rj123-nv pointed out llvm/llvm-project#239023, which is a bug in clang when
handling `[[vk::push_constant]]` applied to a `ConstantBuffer<T>`. This is
especially tricky when it comes to function calls and locals, since DXC allows
silent conversion between the annotated and non-annotated types. There was
general consensus on a direction where we disallow conversion to non-annotated
ConstantBuffer, effectively meaning that the construct can only be used when
the global is accessed directly.

### Lowering to SPIR-V OpTypeMatrix

@farzonl asked about the current state of #506 and what our plans are with
regard to lowering to native SPIR-V matrix types. @dnovillo pointed out that
there's value to doing that, especially for debug info and `spirv-reflect`, but
that any plans in this direction are on the backburner for now.

### Requests for Review

None this week.
